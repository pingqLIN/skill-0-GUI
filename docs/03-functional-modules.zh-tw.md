# 第 3 章：功能模組

英文權威版本：[03-functional-modules.md](./03-functional-modules.md)

返回[繁中說明文件中心](./README.zh-tw.md)。

## 3.1 以任務為起點的匯入

起始工作區先詢問審查目標，不會一次顯示所有控制項：

1. **審查單一技能**：貼上文字、匯入受支援網址或準備相容來源檔案。
2. **審查技能套件**：匯入多個檔案、資料夾或 ZIP，選擇主要技能、
   檢查輔助檔案，並在分析前編輯來源。
3. **接續已存草稿**：還原、匯出、繼續編輯或確認刪除瀏覽器本機草稿。
4. **開啟示範工作台**：載入內建安全內容並走完整審查流程。

匯入側欄會持續顯示目前解析器模式、草稿狀態、近期活動、審查準備狀態與
匯出準備狀態。

## 3.2 來源準備

上傳準備層會：

- 正規化受支援的檔案輸入；
- 找出可能的主要技能檔；
- 區分主要檔案與脈絡檔案；
- 透過動態 JSZip 路徑展開 ZIP；
- 阻擋不安全或定義不清的技能套件；
- 在執行解析器前讓匯入來源可編輯。

網址匯入只處理明確解析且受支援的遠端來源；若要求不受支援或不安全，
會回傳清楚的使用者訊息。

## 3.3 解析器整合

前端會將審查資料送到 `/api/parse-skill`。`bridge/skill0Bridge.mjs` 內的
共享整合邏輯會選擇：

- 已設定的 canonical Skill-0 parser（標準解析器）；
- 內建 standalone fallback（獨立備援）；
- 可選的伺服器端 LLM-assisted recovery（大型語言模型輔助修復）。

每份結果都會包含模式與來源資訊。解析模式會決定可使用的等價性用語與匯出界線。

## 3.4 審查工作台

分析後工作台整合：

- 執行摘要與解析器指標；
- 分解、流程、向量與合規視圖；
- 固定顯示的審查側欄；
- 依優先順序排列的阻擋問題；
- 來源與輔助檔案脈絡；
- 解析器發現事項與來源證據；
- 驗證、一致性與路徑測試證據；
- 審查決策與交接狀態。

介面會明確標示無法取得的證據。工作區層級檢查不得被描述成單一階段
確實執行的證明。

## 3.5 編輯與重新驗證

審查者可以：

- 在結構化編輯器開啟阻擋問題；
- 編輯來源內容或 SkillDocument 欄位；
- 需要結構化脈絡時檢查 JSON；
- 追蹤已修改路徑；
- 比較目前與原始內容；
- 復原或重設編輯；
- 重大修改後重新執行相關檢查。

編輯不會默默提升解析器等價性。重大修改後，匯出流程可能要求重新執行
canonical 解析。

## 3.6 審查決策與簽核

決策層會記錄：

- 全域與元素層級備註；
- 審查狀態；
- 審查者名稱與摘要；
- 決策紀錄；
- 簽核身分；
- 四項簽核檢查；
- 交接狀態；
- 阻擋匯出的原因。

只有在狀態、檢查清單與阻擋證據符合交接門檻後，正式匯出才會啟用。

## 3.7 輸出

工作台可以產生：

- 供人工閱讀的審查報告；
- 機器可讀的審查封包；
- `.skill.md`；
- `.skill.json`；
- 供瀏覽器本機接續工作的 `.draft.json`。

模式、等價性、`canonical_rerun_required` 與僅限草稿欄位都屬於匯出契約。

## 3.8 持久化與在地化

- 工作區草稿儲存在瀏覽器本機 IndexedDB。
- 審查決策狀態儲存在目前瀏覽器設定檔。
- 公開執行環境不提供伺服器端共享持久化。
- 審查介面支援英文與繁體中文。

本機儲存是便利與復原功能，不是協作或資料保存保證。

## 3.9 驗證介面

目前程式庫測試涵蓋：

- 任務式鍵盤導覽；
- 瀏覽器本機草稿還原與匯出；
- 從問題前往編輯器；
- 可編輯的技能套件來源；
- 桌面與行動裝置畫面邊界；
- 嚴重與重大無障礙問題；
- 解析器、伺服器路由與匯出契約。

驗證應以目前原始碼與測試輸出為準。具有日期的報告只記錄特定時間點結果。
