## 1.1 產品定義

`skill-0-GUI` 對外名稱為 **Skill-0 Review Studio**，是 Skill-0 解析結果的
審查工作台。它會將技能來源與解析器證據轉化為結構化的審查、決策與匯出流程。

本產品不是技能執行器，主要責任是：

1. 準備單一技能或含輔助檔案的套件；
2. 呼叫已設定的解析路徑；
3. 讓解析器模式與來源證據保持可見；
4. 呈現驗證、一致性、路徑與審查發現事項；
5. 支援以證據為基礎的編輯與審查決策；
6. 在符合審查要求前鎖定正式匯出。

## 1.2 程式庫邊界

| 程式庫 | 責任 |
|---|---|
| [`skill-0`](https://github.com/pingqLIN/skill-0) | Canonical parser（標準解析器）與共享契約來源 |
| `skill-0-GUI` | 匯入、解析器整合、審查介面、決策狀態與匯出 |

GUI 內含以相容性為導向的 standalone parser（獨立解析器），因此沒有本機
canonical checkout（檢出內容）時仍可執行。standalone 輸出不得宣稱為嚴格
canonical 等價性。

## 1.3 目標使用者

- 核准技能前需要檢查可見證據的審查者
- 需要從問題直接進入編輯器的技能作者
- 將 Skill-0 輸出接到人工審查階段的整合者
- 準備受控內部環境或自包含公開環境的維運者
- 想在不執行技能的前提下評估審查流程的外部利害關係人

## 1.4 主要流程

```text
選擇審查目標
  → 準備單一來源或技能套件
  → 分析
  → 檢查模式、來源、品質檢查與阻擋問題
  → 必要時編輯並重新檢查
  → 記錄決策、檢查清單、摘要與簽核
  → 交接門檻允許後匯出
```

任務式入口提供四種開始方式：

- 審查單一技能；
- 審查技能套件；
- 接續瀏覽器本機草稿；
- 開啟安全示範工作台。

## 1.5 執行模式

| 模式 | 執行行為 | 證據界線 |
|---|---|---|
| `canonical` | 呼叫已設定的本機 `skill-0` parser bridge（解析器橋接） | 最強解析路徑；重大修改後仍可能需要重新執行 |
| `standalone` | 使用內建備援解析器 | 僅供相容性審查，不是嚴格等價性證明 |
| `llm-assisted` | 使用已核准的伺服器端修復介面 | 僅限草稿，絕不是最終等價性證據 |

規範契約位於
[shared/02-mode-and-equivalence-contract.md](./shared/02-mode-and-equivalence-contract.md)。

## 1.6 目前交付內容

- `src/` 內的 React 與 Vite 審查應用程式
- `vite.config.ts` 內的開發階段 API 中介層
- `server.mjs` 內可部署的 Node/Express 執行環境
- `bridge/skill0Bridge.mjs` 內的共享解析器整合
- `standalone/` 內的獨立解析資產
- 瀏覽器本機草稿儲存與草稿匯出
- 審查報告、審查封包、`.skill.md` 與 `.skill.json` 輸出
- 英文與繁體中文產品介面
- 專案內單元、整合、建置、瀏覽器與無障礙品質門檻

`dist/` 是產生的建置產物。可維護的產品權威來源是原始碼驅動的 React 應用程式。

## 1.7 明確不涵蓋的範圍

目前專案不代表已具備：

- 技能執行；
- standalone 或 LLM-assisted 輸出的嚴格等價性；
- 伺服器端文件持久化；
- 多人協作或共享審查歷史；
- 產品內 GitHub Pull Request 自動化；
- 已完成的公開部署。

## 1.8 信任模型

審查產物只有在離開介面後仍保留下列資料時，才具有交接價值：

- 目前解析器模式與模式來源；
- 審查與交接狀態；
- 驗證與審查者證據；
- 等價性狀態；
- `canonical_rerun_required`；
- 僅限草稿的限制。

真實且含操作畫面的流程請接著閱讀
[getting-started.zh-tw.md](./getting-started.zh-tw.md)。
